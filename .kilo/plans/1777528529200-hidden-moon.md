# Territory Standing Optimizer: Comprehensive Implementation Plan

## Executive Summary

**Feature**: Territory Standing Optimizer — calculates the optimal way to spend resources crafting Territory Supplies to maximize standing gain per unit of constrained resource (Azoth, Corrupted Mats, etc.)

**User Value**: In New World's final year with "increased yields and free premium," players will have abundant materials but limited time. This feature answers: _"Given my inventory/budget and all boosters active, which Territory Supplies recipe should I craft and how many times to hit territory standing 300 fastest?"_

**Scope**: Multi-phase rollout from MVP → full optimizer with market integration.

---

## Problem Analysis

### Territory Standing Grinding Reality

Without optimization, players face:

- **4 recipe tiers** (560–5,280 standing per craft)
- **Common bottleneck**: Azoth (200 per craft), Corrupted Mats, Lodestone-tier materials
- **Complex tradeoffs**: Should I craft T1 now or save mats for T4? Should I buy missing mats from TP?
- **Boosters stack**: Territory Standing Gain card (+5% per stack), global yield events (+50–300%), territory bonuses
- **No built-in guide**: Game doesn't prioritize efficiency

### Current Calculator Gap

The existing calculator handles:

- Crafting material requirements for gear
- XP gains from recipes
- Profit margins with market prices

**Missing**: A tool that specifically optimizes for **territory standing points per resource spent**.

## Optimization Formulation

### Objective Function

Maximize total territory standing gained: `Σ (craftCount[i] × standing[i])`

### Decision Variables

- `x1, x2, x3, x4` = number of crafts of T1–T4

### Constraints (Material Balance)

Let `M_azoth`, `M_cf`, `M_cs`, `M_cc`, `M_cl`, `M_sb`, `M_lb`, `M_ov`, `M_rs`, `M_t`, `M_l`, `M_wp`, `M_ip` = available counts of each material.

```
Azoth:    200·x1 + 200·x2 + 200·x3 + 200·x4 ≤ M_azoth
Corrupted Fragment: 20·x1 ≤ M_cf
Corrupted Shard:   10·x2 ≤ M_cs
Corrupted Crystal: 3·x3 ≤ M_cc
Corrupted Lodestone: 2·x4 ≤ M_cl
Stone Brick:       40·x1 ≤ M_sb
Lodestone Brick:   20·x2 ≤ M_lb
Obsidian Voidstone:6·x3 ≤ M_ov
Runestone:         2·x4 ≤ M_rs
Timber:           20·x1 ≤ M_t
Lumber:           20·x2 ≤ M_l
Wyrdwood Planks:  20·x3 ≤ M_wp
Ironwood Planks:  20·x4 ≤ M_ip
```

### Tiered Material Availability (Mixed Inventory)

If player has mixed-tier mats (e.g., 50 Corrupted Shards, 5 Corrupted Crystals), the constraints become:

- Can craft T2 using Shards directly
- Can **downgrade** Crystals to Shards? — NO, one-way only → must use Crystals in T3 or higher
- Can craft T3 using Crystals, but requires also Obsidian Voidstones

Thus we need `x1, x2, x3, x4` to satisfy all material constraints simultaneously.

### Extended Constraints (Optional)

If we allow **material purchase from Trading Post** with gold:

- Add gold constraint: `cost(x1..x4) ≤ goldBudget`
- Where `cost = Σ (materialShortage_i × marketPrice_i)`

If we allow **crafting lower-tier mats from higher-tier** (upgrades allowed):

- Add conversion recipes to material pool (e.g., 1 Crystal → 3 Shards via salvage/craft) — _unlikely_ in NW; crafting is not reversible
- More realistically, **downgrading is impossible**; therefore optimizer must respect tier specificity

### Additive Boosters

Standing gain multipliers stack multiplicatively with recipe standing:

- Territory Standing Gain card: +5% per stack (times count `n_standingGain`)
- Global event "Standing Weekend": +100%
- "Premium free" buff: +25% (hypothetical)

**Effective standing per craft** (with multipliers):

```
effectiveStanding[i] = baseStanding[i] × (1 + standingBonusSum)
```

where `standingBonusSum` is decimal sum of all % bonuses.

This is a **linear objective** with proportionality constant. Maximizing `Σ x_i × baseStanding_i` is equivalent to maximizing effective standing.

## Algorithm Design

### Phase 1 — Simple Single-Constraint Greedy (MVP)

**Approach**: Sort recipes by "standing per limiting resource" and fill accordingly.

1. For each recipe tier i, compute:
   - `maxPossibleByAzoth = floor(M_azoth / 200)`
   - `maxPossibleByCorrupted = floor(M_corruptedTier_i / needed_corrupted_i)`
   - `maxPossibleByBuilding = floor(M_buildingTier_i / needed_building_i)`
   - `maxPossibleByWood = floor(M_woodTier_i / needed_wood_i)`
   - `maxCrafts[i] = min(maxPossibleByAzoth, maxPossibleByCorrupted, maxPossibleByBuilding, maxPossibleByWood)`

2. Sort tiers by `baseStanding[i] / 200` descending (standing per Azoth efficiency)
3. Greedily assign:
   ```
   x4 = maxCrafts[4]; remaining mats -= x4 × usage
   x3 = maxCrafts[3] (after T4 consumption); remaining mats -= x3 × usage
   x2 = maxCrafts[2]; remaining mats -= x2 × usage
   x1 = maxCrafts[1]; remaining mats -= x1 × usage
   ```

**Pros**: O(4×13) ops, trivial, deterministic.
**Cons**: Not globally optimal if materials are imbalanced (e.g., too many T4 mats but not enough Azoth — T4 might still be best even if not first-craft)

### Phase 2 — Multi-Constraint Knapsack (optimal)

Formulate as **integer linear programming (ILP)**:

- Variables: `x1, x2, x3, x4` (non-negative integers)
- Objective: `max 560·x1 + 1000·x2 + 2436·x3 + 5280·x4`
- Constraints: 13 linear inequalities (material availability)

Solve by **enumeration with pruning**:
Since only 4 variables, we can try all combinations bounded by `maxPossible` (typically <1000 each). Use nested loops with early cutting.

**Algorithm**:

```typescript

```

With 4 tiers, worst-case: O(∏ max_i). But `max_i` ≤ `M_azoth/200` (e.g., 5000 Azoth → 25). Feasible.

**Better**: Use **lexicographic ordering** — iterate highest-standing recipe first (T4), then T3, etc. That's greedy but also finds optimum if standing per base ingredient is monotonic (which it is). Greedy is actually optimal here because resource consumption ratios are consistent: every tier uses exactly 200 Azoth, and higher tiers give strictly more standing per Azoth. So the greedy "craft as many T4 as possible, then T3, then T2, then T1" is provably optimal **if Azoth is the binding constraint**. If Azoth is abundant but specific mat is scarce (e.g., only 2 Corrupted Lodestone but plenty of Azoth), greedy still works: T4 limited by Lodestone = 1; then use remaining Azoth for T3, etc.

Thus **greedy by standing/Azoth descending with material caps = optimal** under assumption each recipe consumes Azoth in equal amounts and higher tiers dominate lower tiers on all metrics. Quick proof: T4 gives 26.4 stand/Azoth, T3 gives 12.18, T2 gives 5.0, T1 gives 2.8. Replace 1 T4 with any combination of lower tiers: best you could do is 1 T4 = 5,280. To replace with T3: need 200 Azoth → at most one T3 gives 2,436 (worst). Even if you had infinite lower mats, replacing T4 with T3+T3 impossible (needs 400 Azoth). So greedy optimal.

**Conclusion**: Simple greedy algorithm is optimal. No complex ILP needed.

### Phase 3 — Market Price Integration

If buying missing materials from TP:

- Model materials as **purchasable** at known prices
- Let `budget` = gold available
- For each recipe i, compute:
  - `materialShortage_i = required_i - have_i` (non-negative vector)
  - `costToComplete_i = Σ (shortage_j × price_j)`
  - `netStanding[i] = baseStanding[i]` (fixed)
  - Estimate maximum crafts affordable within gold budget
- Choose recipe to maximize Standing/Gold or Standing/Time

This becomes a **bounded knapsack** where each recipe has weight = gold cost, value = standing. But note:

- Recipes can be crafted multiple times
- Multiple recipe types possible
- Materials partially owned

We can treat as **composite resource** problem:
Ingredients needed if we craft `(x1, x2, x3, x4)`:

```
need_i = Σ_j (usage_{j,i} × xj)  for each material i
shortage_i = max(0, need_i - have_i)
totalGoldCost = Σ_i (shortage_i × price_i)
totalAzothNeeded = Σ_i (usage_{Azoth,j} × xj) // 200 per craft
```

Constraint: `totalGoldCost ≤ goldBudget`

Now optimize: `max Σ baseStanding_j × xj` subject to gold and Azoth.

With 4 recipe types, can brute force by iterating over bounded `x4, x3, x2, x1` with pruning:

- Upper bound: gold budget allows at most `budget / minGoldCostPerCraft` where minGoldCost = cost of cheapest single-material deficit recipe (likely T1)
- But loop over x4 from 0 to floor((goldBudget / costPerT4) or (azoth/200)), then for each compute remaining gold & materials, then x3, etc.
  Complexity: O((maxCrafts)^4). `maxCrafts` bounded by e.g., gold=1M, cheapest craft costs 10 gold => 100k => 100k^4 impossible. Need smarter.

**Alternative**: Use **dynamic programming** for bounded knapsack with multiple resource types? Not trivial.

Better heuristic: **Score each recipe by gold efficiency** (standing per estimated gold cost if we buy all mats), then do greedy by efficiency until gold or Azoth depleted. This is approximate but likely near-optimal if recipes have similar efficiency ranks (T4 > T3 > T2 > T1 when buying all mats). Check if this holds by computing approximate total gold cost of each recipe from market prices (need price data for all mats). T4 uses 2 Corrupted Lodestone (expensive) + Runestone (pricey) + Ironwood Planks (cheap). T1 uses cheap mats. Standing/Azoth ratio: T4 >> T1; standing/gold ratio? Might also be higher because Corrupted Lodestone is very expensive. Need to verify.

We'll design algorithm to optionally consider gold purchasing.
